Parameters

Set shared values once at the root of the run config. methods.setup() derives the child-specific database and decoy settings before writing child parameter JSON files. Settings specific to one child belong in its namespace. Values passed by the metapipeline's child-call processes should not be repeated in a run config.

Root parameter Default Purpose
input_csv Required Sample-to-fraction MS data CSV.
decoy_database Required Target-decoy FASTA.
experiment_type LFQ Selects LFQ or TMT peptide quantitation.
channel_csv Required for TMT Reporter-channel manifest.
msfragger_executable Required for MSFragger Search-engine JAR.
output_dir Required Root directory for published results and logs.
dataset_id cohort Cohort result directory and child project name.
decoy_string / decoy_position DECOY_ / prefix Shared decoy accession marker. MSFragger requires a prefix.
contam_string / contam_position CONTAMINANT_ / prefix Contaminant marker, also checked against the ProtLoom YAML.
child_profile standard Container-runtime profile passed to each child.
proteovault_version 0.2.0 Version used for the ProteoVault image.
docker_image_proteovault ghcr.io/theboutroslab/proteovault:${params.proteovault_version} Container image for the parent ProteoVault process.
compute_profile None Node budget selected by -profile pines, -profile boutroslab_aws, or directly.
additional_resource_profile_dir None Optional PATH-style list of external resource-profile directories.

convert_MSData — optional MS data conversion

An input CSV containing uniform non-mzML paths runs convert-MSData v1.1.1 once for all input samples and fractions. The child writes mzML files under its versioned directory; the parent generates conversion.csv and converted-input.csv manifests and uses the converted mzML for search, validation, quantitation, and QC. Converted files retain their input basenames when these are unique within each sample. If any sample repeats an input basename, every output gains its fraction ID as a suffix. Keep output_format = 'mzML'. Select convert_algorithm = 'ProteoWizard' for supported vendor formats or OpenMS for supported open formats. Peak picking, indexing, and pwiz_extra_args are configured in convert_MSData; see the conversion parameters. The conversion child uses the same child_profile and compute budget as the other children.

search_ProteomicMSMS — database search

Parameter Default Purpose
search_engines ['MSFragger'] Any nonempty combination of Comet, Sage, and MSFragger.
CometAdapter, SageAdapter, MSFraggerAdapter Child defaults Engine-specific tolerances, enzymes, modifications, and other OpenMS adapter settings.
reindex_mzml false Set true to assign unique native scan IDs across a sample's fractions. The reindexed mzML files are passed to validation and peptide quantitation.
export_mzTab false Optional search-stage mzTab export.

The root decoy_string and decoy_position are copied into each selected adapter's PeptideIndexing settings; Sage also receives its decoy_prefix. See the search pipeline configuration and schema for adapter options. Search results are merged per sample and engine before validation.

validate_ProteomicPSM — PSM validation

Parameter Default Purpose
run_percolator true Produce PEP-scored identifications for ProteinProphet.
percolator_workflow openms Use openms or msbooster; the latter adds MSBooster features before direct Percolator scoring.
msbooster_params Child bundled file Optional override for MSBooster prediction settings.
merge_consensus false; enabled automatically for multiple engines Produce one validated consensus idXML per sample for peptide quantitation.
fractionated false Must remain false because search already merges fractions per sample.
run_protloom false Enable ProtLoom inference; currently blocked by the parent protein handoff.
protloom_project_yaml None Base project YAML required with ProtLoom.
protloom_pt_order / protloom_pc_order Empty Required ordering settings when ProtLoom is enabled.
export_easypqp_reports Child default: false DDA does not need EasyPQP reports.

The parent passes the search idXML manifest, the mzML files used for search, and target-decoy FASTA to validation. When search reindexing is enabled, it maps each reindexed file back to its fraction by input CSV order. MSBooster uses the same mzML manifest. The child publishes per-engine filtered idXML and unfiltered PEP-scored idXML; multiple engines also produce a filtered consensus idXML. See the validation pipeline parameters for filtering and inference options.

quantitate_ProteomicTMT — isobaric quantitation

Parameter Default Purpose
plex_type tmt10plex Reporter-label set.
tmt_workflow scan_based Select reporter-scan quantitation or the experimental feature_based MS1 workflow.
tmt_normalization_method Child default Select the TMT normalization route, such as mad.
consensusXML_entrypoint false The metapipeline supplies mzML, idXML, and channel manifests.

The TMT v2.0.0 child receives one validated idXML per plex and the same mzML fractions supplied to validation, including reindexed files when enabled. Channel labels come from channel_csv. For feature_based, give every plex the same set of fraction_id values and set tmt_normalization_method = 'mad' when normalization is enabled. Both TMT workflows publish one dataset-level consensusXML and peptide CSV. See the TMT pipeline parameters for correction matrices, normalization, and reporter-channel options.

quantitate_ProteomicLFQ — label-free quantitation

Parameter Default Purpose
algorithm FFId FeatureFinderIdentification route used by this metapipeline.
fractionated false Set true when each LFQ sample has multiple mzML fractions.
ffid_strategy Child default: merged Identification strategy within FeatureFinderIdentification.
merge_featureXML Child default: true Produce consensusXML for protein quantitation.

The LFQ child receives one validated idXML per sample and the sample-to-fraction mzML manifest. See the LFQ pipeline parameters for feature finding, alignment, and linking options.

quantitate_ProteomicProtein — protein quantitation

Parameter Default Purpose
protein_grouping_algorithm ProteinProphet ProteinProphet or ProteinInferencer.
merge_consensus true Combine the peptide consensusXML files before protein quantitation.
protein_fdr_cutoff 0.01 Protein FDR cutoff when the selected child workflow enables protein FDR filtering.

ProteinProphet also receives the per-engine, PEP-scored idXML files from validation. See the protein pipeline parameters for inference and filtering controls. Root-level decoy_database and decoy_string are passed to this child.

qc_ProteomicDDA — quality control

The QC child runs after protein quantitation. It uses the original mzML fractions, the published unfiltered search and final filtered identification manifests, available PSMFeatureExtractor idXML and MSBooster PIN files from validation, the final ProteinProphet idXML or ProteinInferencer consensusXML, and both ProteinQuantifier abundance tables. Set optional QC-specific parameters in qc_ProteomicDDA; see the QC pipeline parameters. The parent supplies all required input paths, dataset_id, and inference_route.

ProteoVault — cohort database

After QC, the metapipeline builds and validates a ProteoVault v0.2.0 DuckDB database from the published search, validation, TMT or LFQ, protein quantitation, and QC outputs. It supplies the acquisition manifest, target-decoy FASTA, and the channel CSV for TMT. The database includes core quantities, identified TMT reporter observations when available, protein inference, and QC metrics. ProteoVault is skipped when validate_ProteomicPSM.run_protloom = true, because that route does not complete the current protein handoff. The database is published at the versioned metapipeline output root. It records paths from the build work directory; after relocating the result, use proteovault update-paths to update stored source paths. See the ProteoVault v0.2.0 CLI guide.

See config/template.config for an editable run configuration and config/schema.yaml for root parameter validation.
