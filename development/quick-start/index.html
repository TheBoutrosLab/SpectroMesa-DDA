Quick start

  1. Initialize the child pipelines and shared Boutros Lab modules:

bash git submodule update --init --recursive

  1. Prepare the mzML input CSV and a target-decoy FASTA. Obtain the MSFragger JAR separately if MSFragger is selected. For TMT, prepare a channel CSV with the format required by quantitate-ProteomicTMT.

  2. Copy config/template.config to a run-specific file. Set input_csv, decoy_database, output_dir, dataset_id, experiment_type, and the selected search engines. Set channel_csv for TMT and msfragger_executable when using MSFragger. Keep the template's includeConfig lines and final methods.setup() call.

  3. Run with Nextflow 24.10.6 and its v1 syntax parser. Choose a work directory with enough space for the mzML files and child pipeline work:

bash export NXF_VER=24.10.6 export NXF_SYNTAX_PARSER=v1 export NXF_WORK=/scratch/$SLURM_JOB_ID/metapipeline-ProteomicDDA-work nextflow run main.nf -c /path/to/run.config -profile pines

The scratch path is an example for a Slurm job; use another suitable work directory outside Slurm. Select -profile pines for a 64 CPU, 500 GB node or -profile boutroslab_aws for a 32 CPU, 128 GB node. child_profile (standard by default) selects the container runtime in each child; make sure that runtime is available. Nextflow's -c option adds the run configuration to the project's configuration; see the Nextflow configuration documentation.

Resource profiles

Profile Node budget Parent child-launch processes
pines 64 CPUs, 500 GB 2 CPUs, 4 GB per launcher.
boutroslab_aws 32 CPUs, 128 GB 2 CPUs, 4 GB per launcher.

Parent CSV and configuration tasks request 1 CPU and 2 GB; parent child-launch tasks request 2 CPUs and 4 GB from config/resources.json. The bundled JSON profiles set max_cpus and max_memory for the parent and children. Their children process-allocation entries are not applied by the current DDA metapipeline; each child uses its own resource defaults unless its namespace supplies base_resource_update. These profiles describe node budgets; they do not select a Slurm partition or change the local executor.

For a profile outside the repository, copy pines.json or boutroslab_aws.json to a directory you control, rename it <name>.json, and edit its max_cpus and max_memory. Set these values in the run config:

params.compute_profile = 'my_cluster'
params.additional_resource_profile_dir = '/path/to/resource_profiles'

A matching Nextflow -profile entry is not required when compute_profile is set directly. additional_resource_profile_dir can contain multiple directories separated by the operating system's PATH separator (: on Linux/macOS). Lookup checks those directories from left to right, then the bundled config/resource_profiles directory. Relative directories resolve from the launch directory.
